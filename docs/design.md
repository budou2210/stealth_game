# 設計メモ

ゲームの仕様と、設計の考え方をまとめる。
操作方法は [README.md](../README.md)、モジュール構成とテストは [development.md](development.md) を参照。

## 1. 概要
- スニーキューブ（SNEAKUBE）は、Panda3D + Python のステルスゲーム。経路探索はライブラリを使わず、自作のA*で行う（細かく調整するため）。`pathfinding.py`。`Node`クラス + `heapq`、4方向、マンハッタン距離、整数コスト≥1（通路1・壁際3）。
- マップは40×40。20×20の元区画を鏡写しで2×2に並べ、境目（2マス厚）に扉を開ける。スタートは左の外に出っ張った小部屋（安全地帯）。出る（完全に外に出る）と扉が閉まり戻れない。出口は右上で、アイテム全回収で緑になる。
- アイテム8個（各区画2個、毎回ランダム）。警備員は青（順路巡回）10人 + 紫（徘徊）6人。
- 難易度は簡単／普通／難しい／激ムズ／地獄／超越。

- プレイヤー走り4.6 / 忍び足2.2。巡回速度は全難易度共通2.0。捕まる距離0.75。
- 実装は `difficulty.py` の `Difficulty` データクラス。`HELL`を基準に`replace`で`VERY_HARD`→`HARD`と派生（`TRANSCEND`も`HELL`から）。`NORMAL`→`EASY`。警備員の速度は難易度ごとに直接指定（他から継承しない）。

### 警備員のAI（`guard.py`）
- 状態は patrol / search / spotted / chase。視界は扇形 + DDAによる壁越し判定。足音は壁越しだと距離が半分（`SOUND_WALL_MUFFLE`）、追跡中は×1.5で聞こえる。
- 追跡: 進行方向を先読み（`chase_lead_factors`、近い順の役割ごとに強さが違う）。見失うと逃げた方向を外挿（`lost_extrapolations`回）。3マス以内で視界が通れば経路を使わず直線で追う。
- 応援: 追跡中で見えている警備員が`receive_alert(cell, velocity)`で仲間に伝える。激ムズ以上では、仲間は逃げる向きも教わって先回りを狙う。
- 挟み撃ち（`flank_avoid_cost>0`）: `share_alerts`（`app/game.py`）で追っ手を近い順に役割づけ（role）し、近い警備員の通る道を`flank_cells`として後ろの警備員に渡す。2番手以降でプレイヤーから5マス超の警備員（`is_flanker`）は、そのマスに追加コストを足したA*で回り込む。
- 紫（徘徊型）: 目的地はランダム。`focus_rate`の確率で、プレイヤー・未回収アイテム・出口の付近を狙う。全アイテム回収後は`hunting`になり、プレイヤーを決して見失わない。

### 超越の仕掛け（`devices.py`・`app/devices.py`）
超越は「ボットがぎりぎりクリアできる」ように調整する難易度（「ボットができたから理論上は行ける」）。ボットは見つかっていない間の警備員の動きを先読みして動くので、仕掛けはどれも時刻だけで決まる（鳴る床は踏んだときだけ）ようにして、先読みできるようにしてある。見つかった後の強さはボットの難しさに関係しないので、地獄と同じにしている。

| 仕掛け | 置き場所 | 動き |
|---|---|---|
| 見張り番（青緑） | 各区画の (10, 10) とその鏡写し（4人） | 持ち場から動かず、2.5秒ごとに 右→上→左→下 と向きを変える（鏡写しの区画では向きも鏡写し）。見つけた後は普通の鬼と同じで、終わると持ち場に戻る |
| 監視カメラ | 上段の右の部屋の、中央寄りの角（4台） | 部屋の奥へ向けて、±40°の首振りを8秒で1往復（台ごとに2秒ずつずらす）。視界は長さ9・半角22°で、忍び足なら難易度の忍び足の倍率がかかる。すぐそばでも視界の外なら気づかない。映ると、16マス以内（壁越しも）の鬼が映った場所を調べに来る。鳴ったカメラは3秒鳴らない |
| 時間で開け閉めする扉 | 境目の真ん中の扉（縦の境目の y=9、横の境目の x=8 と、その鏡写しで4つ。2×2マス） | 10秒周期で前半5秒開き、後半5秒閉まる（扉ごとに2.5秒ずつずらす）。閉まっている間は壁と同じ（通れず、見通せない）。開いている間は明るい青の枠で囲み、閉まる1.5秒前から枠を黄色と交互に点滅させる。閉まる時刻でも、プレイヤーか鬼が扉の上にいる間は閉めない。鬼は閉まった扉の手前で開くのを待つ |
| 鳴る床（赤と白の縞。ゆっくり点滅） | 部屋の扉と境目の扉（スタート部屋・出口の部屋の扉と、時間で開け閉めする扉を除く32か所）から、ゲームごとに6か所 | 乗った瞬間に音が出る。走って乗ると16マス、忍び足だと6マス以内（壁越しも）の鬼が、その場所を調べに来る（音の罠と同じ反応。全回収後の狩りの鬼は反応しない）。乗ったままでは鳴らず、一度鳴った床は3秒鳴らない |

- 鳴る床の場所は、アイテムの配置の後に乱数で選ぶ（ボットのシミュレーターも同じ順番で選ぶ）。ほかの仕掛けは乱数を使わない。
- 調整値は `constants.py` の「地獄より上の難易度（超越）の仕掛け」。
- 今の数値で決定（2026-11-06）。ボット（巻き戻し60回まで）でのクリア率は32配置中2配置（約6%。種106は378.8秒、種665は332.3秒）。同じボットは地獄なら約8割をクリアする。

### お助けアイテム（地獄以外。`app/helpers.py`）
- 出る種類は難易度で違う: 簡単・普通は透明化・スタン・音の罠の3種、難しい・激ムズはスタンを除く2種（`Difficulty.flash` が False）。
- 20秒ごとに種類別でマップへ1個出現。拾って持ち歩く。上限まで持っている種類、またはマップに出ている種類は出現を数えない。
- **透明化**: 「E」「.」。10秒間、視界に映らず触れても捕まらない。足音は聞かれる。所持上限1。効果中は再使用不可だが、切れればすぐ次を使える（クールタイムなし）。
- **スタン**: 「Q」「/」。使った瞬間にプレイヤーを視界に入れていた警備員は10秒、見ていなくても12マス以内（壁越し含む）は5秒動けない（その間は触れても捕まらない）。所持上限1。安全地帯内では使えない。目が覚めた警備員は、最後に見た場所を調べに行く。
- **音の罠**: 「Space」「\」。足元に設置し、3秒後に音が鳴る（半径16マス、全難易度共通）。範囲内の警備員がその場所を調べに行く（追跡中でも、プレイヤーが見えていなければ引きつけられる）。所持上限2。安全地帯内には置けない。
- **全アイテム回収後に見失わず追ってくる紫（`hunting`）には、お助けアイテムが一切効かない**（スタンも解ける）。

### 操作・視点
- Tab = 視点切替（**全体 → 中間 → 近い → 全体**、開始時は全体）。
- Tab・Enter・お助けキー・Fは毎フレーム`pressed_now`で押下状態を調べる（移動キーを押しっぱなしでも確実に反応させるため）。
- 設定（F）: 足音の範囲の表示。走っている間（安全地帯の外）だけ、足元に2つの範囲を重ねて出す。判定（`Guard.can_hear_within`）と同じ形にしてある。
  - 黄黒の縞（警告テープ風）: 半径`hear_radius`で、壁で切れる形（`World.visible_outline`。視線が通る範囲）。縞は床の座標に固定してあり、プレイヤーが動いても流れない。
  - 赤い円: 壁越しでも聞こえる距離（`hear_radius × SOUND_WALL_MUFFLE`）。壁で切らない。
  - 色を黄・赤の無地にしなかったのは、警備員の視界（見回り＝白、調査＝オレンジ、追跡＝赤）と見分けるため。
- 色の意味は増やしすぎない（見る側が疲れないように）。ふだんの視界は鬼も監視カメラも白（「白い扇＝見られる場所」）。時間で開け閉めする扉は、閉まると壁の仲間と分かる灰色。
  - 縞の上に必ず赤い円が描かれるように、専用の描画グループ（`NOISE_BIN`）で描く順番を固定している。
  - 追跡中の×1.5は表示に含めない。最初はオンで、ゲームを閉じるまで有効（保存はしない）。メニュー・プレイ中のどちらでも切り替えられる。

### 一時停止・ベストタイム
- P で一時停止（プレイ中のみ）。Esc は全画面共通でウィンドウを閉じる（一時停止には使わない）。一時停止中は `update_play` を呼ばず、見た目の更新も dt=0 にして、時間・警備員・回転を全部止める。受け付けるのは P（再開）・R・M・F・Esc だけ。
- ベストタイムは難易度ごとに `records.py` でプロジェクトのフォルダの `saves/records.json` に保存する（場所が分かりやすいように。`.gitignore` の `saves/` で GitHub には上げない）。pyproject.toml が見つからない（フォルダの外にインストールされた）ときは、ユーザーのデータフォルダに保存する。環境変数 `STEALTH_GAME_DATA_DIR` で保存先を変えられる（テストは一時フォルダを使う）。同じタイムは新記録にしない。
- ベスト記録のリプレイ（`replays.py`・`app/replay.py`）：ゲームを始めた時点の乱数の状態（`random.getstate()`）と、プレイ中（捕まって止まっている間も含む）の1コマごとの「時間の長さ・押していた移動と忍び足のキー・押した瞬間のお助けアイテムのキー」を記録する。ベストを更新したら `saves/replays/<難易度>.json.gz` に保存する。再生は同じ乱数の状態から、記録した時間の長さとキーで1コマずつ進めるので、記録と同じ展開になる（乱数を使うのはゲームの進行だけで、視点・足音の範囲の表示・一時停止は展開に影響しない）。乱数の種を決め直すのではなく状態をそのまま残すので、ゲームの動きは記録の機能を入れる前と変わらない。一時停止したコマは記録しない。再生でクリアタイムが記録とずれたり、記録が終わってもクリアしていなかったりしたら「記録と動きが合わなくなりました」と出す。難易度選択の画面では、今のベストタイムと同じタイムのリプレイがある難易度に [再生可] と出し、V で再生する。

- 新記録のジングルは、クリアのジングルの4.0秒後に始める（クリアのジングルは6.5秒あるが、最後の2秒ほどは無音と余韻）。画面も「ミッション成功！ (タイム)」→（ジングルと同時に）「新記録！」に切り替える。新記録でないときは「ミッション成功！ (タイム)」と操作の案内だけを出す（ベストタイムは出さない）。
- 音の罠を置く音は、音が鳴っているのが最初の0.1秒（カチッ）だけで短いので、音量を最大にしている。
- 音量は、ファイルごとの音の大きさを測って揃えている。
- 「使えなかった」は、その難易度で出るお助けアイテムのキーを押したのに、持っていない・透明化中・安全地帯の中で使えなかったとき。

### 画面・テキスト
- 起動したときだけタイトル画面（`app/title.py`）を出し、Enter で難易度選択へ進む。難易度選択に戻るとき（M、クリア・ゲームオーバーの後）はタイトル画面を通らない（やり直すたびにキーを押す手間を増やさないため）。
- タイトル画像（`assets/images/title.jpg`）は、縦横比を保ったまま画面いっぱいに広げる（はみ出した分は切れる）。タイトルの文字は画像に入れず、ゲーム側で重ねる（英語表示に切り替えられるように）。
- タイトル画面から難易度選択までは、同じタイトルの曲を流し続ける。
- 「！」は中間・近い視点では大きく映って邪魔になるので、少し透かす（`EXCLAIM_FOLLOW_ALPHA`）。全体表示では透かさない。
- ウィンドウ名は "SNEAKUBE"。タイトル画面では「SNEAKUBE」の下に、サブタイトル「スニーキューブ ― 箱たちの潜入ゲーム」を出す。
- 日本語フォントが見つからない環境では英語表示。文言は`texts.py`の`TEXTS["ja"/"en"]`にまとまっている。

## 3. 設計方針
- **地獄は、ほぼクリアできない難易度として作っている**。易しくしない。見つからない手段を与えない。
- 激ムズは、お助けアイテムを積極的に使ってほしい難易度。地獄を易しくすると、激ムズが相対的に簡単になる点に注意。
- 追っ手が一列に並ぶと簡単にまけてしまうので、挟み撃ち（`flank`）で後ろの警備員を回り込ませている。
- 紫が注目地点を狙う確率は、難しい10%・激ムズ／地獄30%に抑えている。挟み撃ちと視界の広さで十分に厳しいため。
- 難しい・激ムズではスタンを出さない（透明化と組み合わせると強すぎるため）。
- **超越は、ボットがぎりぎりクリアできる難しさにする**。数値や仕掛けを変えたら、ボット（`tools/bot/`、`--level transcend`）でクリアできることを確かめる。
