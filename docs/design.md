# 設計メモ

コードを読むだけでは分かりにくい、仕様の一覧・設計方針・未検証の点・保留中の案をまとめる。
操作方法は [README.md](../README.md)、モジュール構成とテストは [development.md](development.md) を参照。

## 1. 概要
- Panda3D + Python のステルスゲーム。経路探索は自作A*（`pathfinding.py`。`Node`クラス + `heapq`、4方向、マンハッタン距離、整数コスト≥1。通路1・壁際3）。**A*は自作を維持**し、ライブラリに置き換えない。
- マップは40×40。20×20の元区画を鏡写しで2×2に並べ、境目（2マス厚）に扉を開ける。スタートは左の外に出っ張った小部屋（安全地帯）。出る（完全に外に出る）と扉が閉まり戻れない。出口は右上で、アイテム全回収で緑になる。
- アイテム8個（各区画2個、毎回ランダム）。警備員は青（順路巡回）10人 + 紫（徘徊）6人。
- 難易度は簡単／普通／難しい／激ムズ／地獄。

## 2. 仕様
| 項目 | 簡単 | 普通 | 難しい | 激ムズ | 地獄 |
|---|---|---|---|---|---|
| 視界の長さ | 8 | 8 | 9 | 10 | 10 |
| 視野角 | 70° | 70° | 75° | 80° | 80° |
| 忍び足の視認倍率 | .65 | .65 | .72 | .8 | .8 |
| 警戒の上がりやすさ | 1 | 1 | 1.6 | 1.6 | 1.6 |
| 足音の届く距離 | 2.5 | 2.5 | 3 | 6.5 | 6.5 |
| 追跡速度 | 3.1 | 3.1 | 3.96 | 3.96 | 4.4 |
| 捜索速度 | 2.8 | 2.8 | 3.2 | 3.2 | 3.2 |
| 「！」後の間 | .5s | .5s | .5s | .5s | 0（即追跡） |
| 応援（仲間を呼ぶ）半径 | なし | なし | 8（近い2人まで） | 16 | 16 |
| 挟み撃ち（回避コスト） | なし | なし | なし | 6 | 6 |
| 紫が注目地点を狙う確率 | – | – | 10% | 30% | 30% |
| 全回収後の紫の強制追跡 | なし | なし | あり | あり | あり |
| 紫の有無 | なし | あり | あり | あり | あり |
| ライフ | 3 | 2 | 1 | 1 | 1 |
| お助けアイテム | 3種 | 3種 | 透明化・音の罠 | 透明化・音の罠 | **なし** |

- プレイヤー走り4.6 / 忍び足2.2。巡回速度は全難易度共通2.0。捕まる距離0.75。
- 実装は `difficulty.py` の `Difficulty` データクラス。`HELL`を基準に`replace`で`VERY_HARD`→`HARD`と派生。`NORMAL`→`EASY`。鬼の速度は難易度ごとに直接指定（他から継承しない）。

### 鬼のAI（`guard.py`）
- 状態は patrol / search / spotted / chase。視界は扇形 + DDAによる壁越し判定。足音は壁越しだと距離が半分（`SOUND_WALL_MUFFLE`）、追跡中は×1.5で聞こえる。
- 追跡: 進行方向を先読み（`chase_lead_factors`、近い順の役割ごとに強さが違う）。見失うと逃げた方向を外挿（`lost_extrapolations`回）。3マス以内で視界が通れば経路を使わず直線で追う。
- 応援: 追跡中で見えている鬼が`receive_alert(cell, velocity)`で仲間に伝える。激ムズ以上では、仲間は逃げる向きも教わって先回りを狙う。
- 挟み撃ち（`flank_avoid_cost>0`）: `share_alerts`（`app/game.py`）で追っ手を近い順に役割づけ（role）し、近い鬼の通る道を`flank_cells`として後ろの鬼に渡す。2番手以降でプレイヤーから5マス超の鬼（`is_flanker`）は、そのマスに追加コストを足したA*で回り込む。
- 紫（徘徊型）: 目的地はランダム。`focus_rate`の確率で、プレイヤー・未回収アイテム・出口の付近を狙う。全アイテム回収後は`hunting`になり、プレイヤーを決して見失わない。

### お助けアイテム（地獄以外。`app/helpers.py`）
- 出る種類は難易度で違う: 簡単・普通は透明化・スタン・音の罠の3種、難しい・激ムズはスタンを除く2種（`Difficulty.flash` が False）。
- 20秒ごとに種類別でマップへ1個出現。拾って持ち歩く。上限まで持っている種類、またはマップに出ている種類は出現を数えない。
- **透明化**: 「E」「.」。10秒間、視界に映らず触れても捕まらない。足音は聞かれる。所持上限1。効果中は再使用不可だが、切れればすぐ次を使える（クールタイムなし）。
- **スタン**: 「Q」「/」。使った瞬間にプレイヤーを視界に入れていた鬼は10秒、見ていなくても12マス以内（壁越し含む）は5秒動けない（その間は触れても捕まらない）。所持上限1。安全地帯内では使えない。目が覚めた鬼は、最後に見た場所を調べに行く。
- **音の罠**: 「Space」「\」。足元に設置し、3秒後に音が鳴る（半径16マス、全難易度共通）。範囲内の鬼がその場所を調べに行く（追跡中でも、プレイヤーが見えていなければ引きつけられる）。所持上限2。安全地帯内には置けない。
- **全アイテム回収後に見失わず追ってくる紫（`hunting`）には、お助けアイテムが一切効かない**（スタンも解ける）。
- 共通クールタイム・副作用は**まだ実装していない**（§6参照）。

### 操作・視点
- Tab = 視点切替（**全体 → 中間 → 近い → 全体**、開始時は全体）。
- Tab・Enter・お助けキー・Fは毎フレーム`pressed_now`で押下状態を調べる（移動キーを押しっぱなしでも確実に反応させるため）。
- 設定（F）: 足音の範囲の表示。走っている間（安全地帯の外）だけ、足元に2つの範囲を重ねて出す。判定（`Guard.can_hear_within`）と同じ形にしてある。
  - 黄黒の縞（警告テープ風）: 半径`hear_radius`で、壁で切れる形（`World.visible_outline`。視線が通る範囲）。縞は床の座標に固定してあり、プレイヤーが動いても流れない。
  - 赤い円: 壁越しでも聞こえる距離（`hear_radius × SOUND_WALL_MUFFLE`）。壁で切らない。
  - 色を黄・赤の無地にしなかったのは、警備員の視界（見回り＝黄、調査＝オレンジ、追跡＝赤）と見分けるため。
  - 描く順番は専用の描画グループ（`NOISE_BIN`）で「縞 → 赤い円」に固定してある。半透明の既定の描画グループはカメラから遠い順に描くので、縞の形が手前に寄る場所では縞が赤い円の上に重なっていた。
  - 追跡中の×1.5は表示に含めない。最初はオンで、ゲームを閉じるまで有効（保存はしない）。メニュー・プレイ中のどちらでも切り替えられる。

### 一時停止・ベストタイム
- P で一時停止（プレイ中のみ）。Esc は全画面共通でウィンドウを閉じる（一時停止には使わない）。一時停止中は `update_play` を呼ばず、見た目の更新も dt=0 にして、時間・警備員・回転を全部止める。受け付けるのは P（再開）・R・M・F・Esc だけ。
- ベストタイムは難易度ごとに `records.py` でプロジェクトのフォルダの `saves/records.json` に保存する（場所が分かりやすいように。`.gitignore` の `saves/` で GitHub には上げない）。pyproject.toml が見つからない（フォルダの外にインストールされた）ときは、ユーザーのデータフォルダに保存する。環境変数 `STEALTH_GAME_DATA_DIR` で保存先を変えられる（テストは一時フォルダを使う）。同じタイムは新記録にしない。

### 画面・テキスト
- ウィンドウ名は "Stealth Game"。
- 日本語フォントが見つからない環境では英語表示。文言は`texts.py`の`TEXTS["ja"/"en"]`にまとまっている。

## 3. 設計方針
- **地獄は「クリアさせる気はない、やれるものならやってみろ」のまま維持**。易化しない。見つからない手段を与えない。
- 激ムズは現状で良い難易度。「アイテムを極限まで活用して、ようやくクリアできる」ことを目標にしている（実績: 283.6秒クリア）。地獄を易化させると激ムズが相対的に簡単になる点に注意。
- 「列を作る」戦法（追っ手が一列に並ぶ弱点）は、挟み撃ち（`flank`）の追加で意図的に潰した。
- 紫の脅威度は下げ済み（難しい10%、激ムズ・地獄30%）。挟み撃ちと視界の広さでも十分に厳しい。
- お助けアイテムのパワーバランスが議論点。「スタン + 透明化」のコンボが強すぎ、「スタン→透明化」の順だと副作用を踏み倒せる、音は使われない、という問題が出た（対応案は§6）。
  - 難しい・激ムズでは透明化・スタンの両方を出さない案も一度入れたが取りやめ、スタンだけを出さないことにした（2026-11-03）。
    これでコンボは成立しなくなったので、§6の共通クールタイム・副作用の案が関係するのは簡単・普通だけになった。

## 4. テスト方法
- Panda3Dを使わずに動かす場合は、`panda3d`と`direct`を`sys.modules[...] = MagicMock()`で差し替え、`ShowBase`をスタブにしてから`stealth_game.app.game`を読み込む。`StealthGame`を作り、`is_down`をボットの入力に差し替えて`update_play(1/60)`などを回す。
  - `update_visuals`はMagicMockの呼び出し記録でメモリを大量に使うので、長時間回すときは外す。
- 挙動比較: 乱数の種とボットの動きを固定し、鬼の位置・状態・経路をフレームごとに比べる（リファクタリング前後の同値確認に使う）。
- 長時間シミュレーション: 例外が出ないこと、A*再計算の負荷（スパイク）を見る。音の罠発動時のスパイクは、範囲20マスの版で測定して平均9.3ms / 最悪14.9ms（現在の範囲16では未測定）。
- 実際のPanda3Dでの起動確認は `window-type offscreen` で可能。ただしオフスクリーンでは`mouseWatcherNode`がないので、`bind_events`と`is_down`を差し替える。
- 過去に検証済みの内容: 挟み撃ちの経路重なり（28%→1%）、スタン・透明化・音の罠の動作。

## 5. 未検証・注意点
- **描画は未検証**: スタン中の鬼の見た目（灰色で回転）、広がる円、ヒント文の長さ、「！」の表示など。実機で見る必要がある。
  - オフスクリーン描画のスクリーンショットで確認済み（2026-11-03）: 難易度選択の画面が収まること、操作説明の長さ、中間・近い視点、足音の範囲の表示（縞と赤い円）。
  - オフスクリーン描画は `window-type offscreen` で起動し、`base.win.saveScreenshot()` で撮れる（`bind_events` と `is_down` は差し替える）。
- `\`キーは日本語キーボードでは「¥」（「ろ」の位置）になる。キーマッピングが想定通りか未確認。
- 実機でのパフォーマンス（鬼16人 + 視界の扇形の描画）は未確認。

## 6. 保留中の案
- 方針として決めたが**未実装**（透明化とスタンの両方が関係する案は、今は簡単・普通だけが対象）:
  - 透明化とスタンの共通クールタイム15秒（音の罠は対象外）
  - 透明化の副作用: 切れた瞬間に周囲20マスの紫に気配を察知される
  - スタンの副作用: 使用時に効果範囲外（12〜20マス）の鬼が気配を察知する
  - 音の罠の範囲 16→20（二度鳴らす案や削除案も出たが、範囲拡大のみ採用と決めた）
- 次にやりそうなこと: 上記の実装、実機プレイの所感に基づく難易度調整、スタン・透明化の見た目の確認と修正。
